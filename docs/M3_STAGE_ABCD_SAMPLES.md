# M3 七段生命周期 + A/B/C/D 样例数据

来源：群聊业务负责人确认；TECH_SPEC 第 9 节晋级规则冻结。

本文供测试与后端实现对照。下列判定写死，验收时按样例过/不过，不另加口径。

## 七段正向晋级

| 从 | 到 | 过（必须满足） | 不过（反例） |
| --- | --- | --- | --- |
| LEAD 线索 | INQUIRY 询盘 | 有效询盘：品名/数量/目的港至少一项。例：询「DN50 球阀，20 柜，目的港 Rotterdam」 | 仅备注「已联系」 |
| INQUIRY 询盘 | NEGOTIATION 谈判 | 已报价且客户有回复。例：报价单 Q-2026-001 + 客户回「能否再降 5%」 | 只发报价无回复 |
| NEGOTIATION 谈判 | WON 成交 | 有订单号或合同号。例：合同号 CT-8891 已回签 | 无单号仅口头意向 |
| WON 成交 | SHIPPED 发货 | 有货运/出运单证号。例：BL-77821 | 无单证号 |
| SHIPPED 发货 | AFTERSALES 售后 | 有签收确认或到货反馈 | 无签收/反馈 |

调用方不能手填目标阶段；仅「已联系」不能升迁。实现见 `StagePromotionPolicy.forward`。

## 流失与唤醒

- 明确拒绝：客户写「we decided not to proceed」→ 标 LOST，进唤醒序列
- 30 天无有效互动 → 标 LOST，进唤醒序列
- 流失判定用 `shouldMarkLost`，与正向升迁不要写进同一次更新
- 唤醒序列属阶段⑤，当前可占位

## A/B/C/D 客户等级（写死判定）

| 等级 | 判定 |
| --- | --- |
| A | 近 90 天有成交，或明确预算+交货期 |
| B | 有效询盘且有报价往来，未成交 |
| C | 仅线索/弱意向，30 天内有互动 |
| D | 长期无互动或多次未回复（接近公海） |

## 揭盲样例（经理）

- 原因示例：「投诉核实客户原询盘」（≥8 字，不含 `@` 与连续 8 位数字）
- 默认时长 15 分钟；开始/结束/过期写审计；业务员 403
